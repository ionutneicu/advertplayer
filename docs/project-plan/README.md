### Project plan

Sequencing, risk and decision state. **What** the system must do lives in
[../architecture/](../architecture/); this folder is **when**, **in what
order**, and **what is still undecided**.

| Document | Contents |
| -------- | -------- |
| [roadmap.md](roadmap.md) | Phase tags, the five delivery steps, what is currently in scope |
| [stories.md](stories.md) | The PoC broken into eight deliverable stories, with acceptance criteria |
| [status.md](status.md) | Whether the PoC is ready to start, and what to watch while building it |
| [open-decisions.md](open-decisions.md) | Decisions taken, and those outstanding with proposed defaults |
| [risks.md](risks.md) | Every non-PoC item, what it costs to retrofit, and the mitigation the PoC must carry now |
| [prior-implementation.md](prior-implementation.md) | The 2017–2025 codebase: what carries over, what is superseded, what was never finished |
| [research-notes.md](research-notes.md) | Problems understood well enough to write down, not well enough to specify |

Requirement identifiers (`FR-n`, `NFR-n`, `OUT-n`) refer to
[../architecture/requirements.md](../architecture/requirements.md). Open points
(`OP-n`) and risks (`R-n`) are defined here.

##### Reading order

1. **roadmap.md** — what is being built, and when.
2. **status.md** — whether it can start.
3. **open-decisions.md** — what the reviewer is being asked to rule on.
4. **risks.md** — the constraints those decisions impose on PoC code.
